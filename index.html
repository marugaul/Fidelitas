Paradigma 01 / 08

Programación
Imperativa

Le dices a la computadora exactamente cómo hacer cada cosa, paso a paso. El programa es una secuencia de instrucciones que van cambiando el estado de las variables. Es el paradigma más cercano al hardware — así funciona la máquina debajo de todo. Lenguajes representativos: C, Pascal.

estado mutable variables bucles condicionales secuencia de pasos asignación
Python
# Suma de cuadrados de números pares del 1 al 10
# Instrucción por instrucción — el programador controla todo

total = 0
i = 1

while i <= 10:
    if i % 2 == 0:               # ¿Es par?
        cuadrado = i * i
        total = total + cuadrado
    i = i + 1

print("Suma de cuadrados de pares:", total)
# → 220   (4 + 16 + 36 + 64 + 100)

Dónde se usa

Scripts de automatización

Tareas repetitivas donde el orden de los pasos importa.

Algoritmos de bajo nivel

Control total del flujo para optimizar el rendimiento.

Manipulación de archivos

Procesar línea por línea con control explícito del estado.

Ventajas y desventajas

Ventajas

  • Intuitivo — se piensa como una receta
  • Control total sobre cada paso
  • Eficiente en uso de memoria

Desventajas

  • Difícil de razonar en programas grandes
  • Propenso a efectos secundarios
  • Código difícil de reutilizar
Paradigma 02 / 08

Programación
Procedimental

Evolución del imperativo: en lugar de repetir instrucciones, se agrupan en funciones o procedimientos con nombre. Cada función resuelve una tarea específica y puede llamarse desde cualquier parte del programa. Divide el problema en subproblemas más pequeños. Lenguajes: C, Pascal.

funciones procedimientos modularidad reutilización parámetros llamadas anidadas
Python
# Ordenamiento burbuja con funciones reutilizables
# Cada función tiene una sola responsabilidad

def es_mayor(a, b):
    return a > b

def intercambiar(lista, i, j):
    lista[i], lista[j] = lista[j], lista[i]

def burbuja(lista):
    n = len(lista)
    for i in range(n):
        for j in range(0, n - i - 1):
            if es_mayor(lista[j], lista[j + 1]):
                intercambiar(lista, j, j + 1)
    return lista

def imprimir_resultado(original, ordenada):
    print("Original:", original)
    print("Ordenada:", ordenada)

notas = [7.5, 9.2, 4.8, 8.0, 6.3]
resultado = burbuja(notas.copy())
imprimir_resultado(notas, resultado)
# → Original: [7.5, 9.2, 4.8, 8.0, 6.3]
# → Ordenada: [4.8, 6.3, 7.5, 8.0, 9.2]

Dónde se usa

Programas en C

Sistemas embebidos y código de sistema con funciones bien definidas.

Herramientas CLI

Lógica dividida en operaciones específicas y reutilizables.

Procesamiento de datos

Pipelines de transformación con pasos claros y separados.

Ventajas y desventajas

Ventajas

  • Código organizado y reutilizable
  • Más fácil de depurar por partes
  • Divide problemas complejos en tareas

Desventajas

  • Puede haber estado global accidental
  • Escalabilidad limitada en proyectos grandes
  • Sin encapsulamiento real de datos
Paradigma 03 / 08

Orientada
a Objetos

Organiza el código en objetos que combinan datos (atributos) y comportamiento (métodos). Los objetos son instancias de clases y se relacionan mediante herencia, encapsulamiento y polimorfismo. Permite modelar el mundo real directamente en el código.

clases objetos herencia encapsulamiento polimorfismo abstracción
Python
# Figuras geométricas con herencia y polimorfismo
import math

class Figura:
    def __init__(self, color):
        self.__color = color        # Privado — encapsulamiento

    def color(self):
        return self.__color

    def area(self):                 # Abstracto — cada clase lo define
        raise NotImplementedError

    def describir(self):
        return f"{type(self).__name__} {self.__color}: área = {self.area():.2f}"


class Circulo(Figura):
    def __init__(self, color, radio):
        super().__init__(color)
        self.radio = radio

    def area(self):                 # Polimorfismo: mismo nombre, distinto cálculo
        return math.pi * self.radio ** 2


class Rectangulo(Figura):
    def __init__(self, color, ancho, alto):
        super().__init__(color)
        self.ancho = ancho
        self.alto  = alto

    def area(self):
        return self.ancho * self.alto


class Triangulo(Figura):
    def __init__(self, color, base, altura):
        super().__init__(color)
        self.base   = base
        self.altura = altura

    def area(self):
        return (self.base * self.altura) / 2


# Mismo método .describir() en cada objeto — polimorfismo en acción
figuras = [
    Circulo("rojo", 5),
    Rectangulo("azul", 4, 6),
    Triangulo("verde", 3, 8),
]

for f in figuras:
    print(f.describir())
# → Circulo rojo: área = 78.54
# → Rectangulo azul: área = 24.00
# → Triangulo verde: área = 12.00

Dónde se usa

Videojuegos

Personajes, objetos y escenarios como clases con comportamientos propios.

Aplicaciones empresariales

Modelos de dominio: Cliente, Factura, Producto encapsulados.

Interfaces gráficas

Botones, ventanas y controles como objetos con eventos y estado.

Ventajas y desventajas

Ventajas

  • Modela el mundo real de forma natural
  • Reutilización por herencia
  • Alta escalabilidad en proyectos grandes

Desventajas

  • Jerarquías profundas difíciles de mantener
  • Overhead innecesario para tareas simples
  • Estado compartido puede causar bugs sutiles
Paradigma 04 / 08

Programación
Funcional

Trata la computación como evaluación de funciones matemáticas puras. Sin estado mutable, sin efectos secundarios. El mismo input siempre produce el mismo output. Las funciones se pasan como argumentos, se devuelven como valores y se componen. Lenguajes: Haskell, Lisp, Erlang.

funciones puras inmutabilidad composición map / filter / reduce lambdas recursión sin efectos secundarios
Python
# Procesar calificaciones con funciones puras
# Ninguna función modifica los datos originales
from functools import reduce

calificaciones = [4.5, 8.2, 9.0, 3.7, 7.5, 8.8, 5.1, 9.5]

# Funciones puras: mismo input → mismo output, siempre
aprobado      = lambda nota: nota >= 6.0
al_porcentaje = lambda nota: round((nota / 10) * 100, 1)
sumar         = lambda a, b: a + b

# Composición: filtrar → transformar → reducir
aprobados   = list(filter(aprobado, calificaciones))
porcentajes = list(map(al_porcentaje, aprobados))
total       = reduce(sumar, porcentajes, 0)
promedio    = total / len(porcentajes)

def estadisticas(notas):            # También pura: no modifica 'notas'
    ordenadas = sorted(notas)
    return {
        "min":   ordenadas[0],
        "max":   ordenadas[-1],
        "media": reduce(sumar, notas, 0) / len(notas),
    }

print("Aprobados: ", aprobados)
print("Promedio:  ", promedio, "%")
print("Stats:     ", estadisticas(aprobados))
# → Aprobados:  [8.2, 9.0, 7.5, 8.8, 9.5]
# → Promedio:   86.0 %
# → Stats:      {'min': 7.5, 'max': 9.5, 'media': 8.6}

Dónde se usa

Procesamiento de datos

Transformaciones en pipelines: ETL, análisis, reportes.

Concurrencia

Sin estado mutable, no hay condiciones de carrera al paralelizar.

Testing

Funciones puras son trivialmente testeables — sin mocks ni setup.

Ventajas y desventajas

Ventajas

  • Código predecible y fácil de probar
  • Seguro en contextos concurrentes
  • Composición produce código conciso

Desventajas

  • Curva alta (mónadas, recursión profunda)
  • Puede crear muchas copias de datos en memoria
  • No encaja bien con I/O o estado inherente
Paradigma 05 / 08

Programación
Declarativa

Describes qué querés obtener, no cómo lograrlo. El programador declara el objetivo y el motor o intérprete decide la mejor estrategia. SQL es el ejemplo más conocido: describes la consulta y la base de datos decide si usar un índice, un escaneo completo, etc.

qué vs cómo expresiones sin efectos secundarios alto nivel de abstracción el motor optimiza
SQL
-- Tabla: estudiantes
-- id | nombre       | nota | carrera
-- ---|--------------|------|----------
-- 1  | Ana García   | 9.2  | Sistemas
-- 2  | Luis Mora    | 7.5  | Informática
-- 3  | Sara López   | 8.8  | Sistemas
-- 4  | Pedro Ruiz   | 5.9  | Sistemas

-- Declaramos QUÉ queremos — el motor decide CÓMO buscarlo
SELECT
    nombre,
    nota,
    CASE
        WHEN nota >= 9.0 THEN 'Sobresaliente'
        WHEN nota >= 7.0 THEN 'Notable'
        ELSE 'Aprobado'
    END AS distincion
FROM estudiantes
WHERE carrera = 'Sistemas'
  AND nota >= 6.0
ORDER BY nota DESC;

-- Resultado:
-- Ana García  | 9.2 | Sobresaliente
-- Sara López  | 8.8 | Notable
HTML + CSS
<!-- Declaramos ESTRUCTURA y ESTILO, no el algoritmo de render -->
<style>
  .tarjeta {
    display: flex;       /* El navegador decide cómo distribuir */
    gap: 16px;
    border-radius: 8px;
    padding: 20px;
  }
  .nota-alta { color: green; font-weight: bold; }
</style>

<div class="tarjeta">
  <span>Ana García</span>
  <span class="nota-alta">9.2</span>
</div>

Dónde se usa

Bases de datos (SQL)

Consultas complejas sin escribir algoritmos de búsqueda.

Interfaces web (HTML/CSS)

Estructura y estilo sin código de renderizado manual.

Infraestructura (Terraform)

Declarar el estado deseado del sistema, no los pasos para llegar.

Ventajas y desventajas

Ventajas

  • Código muy legible y conciso
  • El motor puede optimizar mejor que nosotros
  • Menos errores de lógica de control

Desventajas

  • Menor control sobre el rendimiento
  • Depuración más difícil (el motor es opaco)
  • Dependiente de las capacidades del intérprete
Paradigma 06 / 08

Programación
Reactiva

El programa reacciona a flujos de datos y eventos en lugar de ejecutar instrucciones en orden fijo. Los componentes se suscriben a fuentes de datos y se actualizan automáticamente cuando algo cambia. Es la base de frameworks modernos como React y Vue. Lenguaje representativo: JavaScript.

flujos de datos eventos observadores suscriptores asincronía propagación de cambios
JavaScript
// Monitoreo de temperatura con patrón Observador
// Los suscriptores reaccionan cuando el dato cambia

class FlujoDatos {
  constructor() {
    this._subs = {};
  }

  on(evento, fn) {
    if (!this._subs[evento]) this._subs[evento] = [];
    this._subs[evento].push(fn);
    return this;
  }

  emitir(evento, datos) {
    (this._subs[evento] || []).forEach(fn => fn(datos));
  }
}

const sensor = new FlujoDatos();

// Cada suscriptor define su propia reacción
sensor.on('temperatura', temp => {
  if (temp > 37.5) console.log(`ALERTA: fiebre (${temp}°C)`);
});

const historial = [];
sensor.on('temperatura', temp => {
  historial.push({ temp, hora: new Date().toLocaleTimeString() });
  console.log(`Registrado: ${temp}°C — total: ${historial.length} lecturas`);
});

sensor.emitir('temperatura', 36.5);
// → Registrado: 36.5°C — total: 1 lecturas

sensor.emitir('temperatura', 38.2);
// → ALERTA: fiebre (38.2°C)
// → Registrado: 38.2°C — total: 2 lecturas

Dónde se usa

Interfaces reactivas

React, Vue: la UI se actualiza sola cuando cambia el estado.

Streaming de datos

Eventos en tiempo real: precios bursátiles, mensajes, sensores.

Sistemas IoT

Dispositivos que reaccionan a lecturas de sensores al instante.

Ventajas y desventajas

Ventajas

  • Maneja la asincronía elegantemente
  • Desacoplamiento entre emisores y receptores
  • Ideal para múltiples fuentes de datos

Desventajas

  • El flujo de datos es difícil de rastrear
  • Cascadas de eventos generan bugs sutiles
  • Curva alta con RxJS y Observables
Paradigma 07 / 08

Programación
Lógica

Basado en lógica formal: defines hechos y reglas, y un motor de inferencia calcula las respuestas. No programas el camino hacia la solución — declaras lo que sabes y dejas que el motor explore con backtracking todas las combinaciones posibles. Lenguaje: Prolog.

hechos reglas consultas backtracking unificación motor de inferencia
Prolog — Relaciones familiares
% === HECHOS: lo que sabemos que es verdad ===
progenitor(carlos, ana).
progenitor(carlos, luis).
progenitor(ana,    sofia).
progenitor(ana,    miguel).
progenitor(luis,   paula).

masculino(carlos).  masculino(luis).   masculino(miguel).
femenino(ana).      femenino(sofia).   femenino(paula).

% === REGLAS: relaciones que se derivan ===
% "X :- Y" se lee: X es verdad SI Y es verdad
padre(X, Y)   :- progenitor(X, Y), masculino(X).
madre(X, Y)   :- progenitor(X, Y), femenino(X).
abuelo(X, Z)  :- progenitor(X, Y), progenitor(Y, Z).
hermano(X, Y) :- progenitor(Z, X), progenitor(Z, Y), X \= Y.

% Recursiva: ancestro en cualquier generación
ancestro(X, Y) :- progenitor(X, Y).
ancestro(X, Y) :- progenitor(X, Z), ancestro(Z, Y).

% === CONSULTAS — el motor infiere las respuestas ===
% ?- padre(carlos, ana).       →  true
% ?- abuelo(carlos, sofia).    →  true
% ?- hermano(sofia, X).        →  X = miguel
% ?- ancestro(carlos, paula).  →  true  (carlos→luis→paula)
Prolog — Colorear un mapa (restricciones)
% Regiones adyacentes no pueden tener el mismo color
color(rojo).  color(verde).  color(azul).

adyacente(a, b).  adyacente(b, c).
adyacente(a, c).  adyacente(c, d).

colorear(CA, CB, CC, CD) :-
    color(CA), color(CB), color(CC), color(CD),
    CA \= CB,   CB \= CC,   CA \= CC,   CC \= CD.

% ?- colorear(CA, CB, CC, CD).
% El motor aplica backtracking sobre todas las combinaciones
% → CA=rojo, CB=verde, CC=azul, CD=rojo  (entre otras soluciones)

Dónde se usa

Sistemas expertos

Diagnóstico médico o legal basado en reglas de conocimiento.

IA simbólica

Razonamiento formal, planificación automática de tareas.

Restricciones (CSP)

Horarios, asignaciones, Sudoku — el motor encuentra soluciones.

Ventajas y desventajas

Ventajas

  • Muy expresivo para modelar relaciones
  • El motor encuentra todas las soluciones posibles
  • Natural para problemas de deducción

Desventajas

  • Rendimiento impredecible — backtracking escala mal
  • Poco uso en producción fuera de IA académica
  • Requiere cambiar la forma de pensar completamente
Paradigma 08 / 08

Programación
Concurrente y Paralela

Diseña programas que ejecutan múltiples tareas al mismo tiempo. La concurrencia intercala tareas que progresan independientemente (no necesariamente al mismo instante), mientras que el paralelismo las ejecuta literalmente en simultáneo usando múltiples núcleos. Lenguajes: Go (concurrente), CUDA (paralela en GPU).

goroutines canales hilos / threads mutex / lock race condition paralelismo en GPU concurrencia vs paralelismo
Go — goroutines y canales
// Descargar 5 páginas concurrentemente
// Sin goroutines: ~5s. Con goroutines: ~1s.

package main

import (
    "fmt"
    "sync"
    "time"
)

func descargar(url string, id int, wg *sync.WaitGroup, res chan<- string) {
    defer wg.Done()
    time.Sleep(1 * time.Second)  // simula latencia de red
    res <- fmt.Sprintf("Descargado [%d]: %s", id, url)
}

func main() {
    urls := []string{
        "fidelitas.ac.cr/cursos",
        "fidelitas.ac.cr/noticias",
        "fidelitas.ac.cr/biblioteca",
        "fidelitas.ac.cr/campus",
        "fidelitas.ac.cr/horarios",
    }

    resultados := make(chan string, len(urls))
    var wg sync.WaitGroup
    t0 := time.Now()

    for i, url := range urls {
        wg.Add(1)
        go descargar(url, i+1, &wg, resultados)  // 'go' lanza una goroutine
    }

    go func() { wg.Wait(); close(resultados) }()

    for r := range resultados {
        fmt.Println(r)
    }
    fmt.Printf("Total: %.2fs  (sin go: ~5s)\n", time.Since(t0).Seconds())
}
// El orden de llegada es no-determinista:
// → Descargado [3]: fidelitas.ac.cr/biblioteca
// → Descargado [1]: fidelitas.ac.cr/cursos  ...
// → Total: 1.00s
Python — Race condition y su solución
# El bug clásico de concurrencia y cómo prevenirlo
import threading

# ❌ SIN lock — resultado impredecible
contador_inseguro = 0

def incrementar_inseguro():
    global contador_inseguro
    for _ in range(100_000):
        contador_inseguro += 1   # leer-modificar-escribir NO es atómico

# ✅ CON lock — resultado garantizado
contador_seguro = 0
lock = threading.Lock()

def incrementar_seguro():
    global contador_seguro
    for _ in range(100_000):
        with lock:               # solo un hilo a la vez entra aquí
            contador_seguro += 1

# Lanzar 5 hilos para cada versión
hi = [threading.Thread(target=incrementar_inseguro) for _ in range(5)]
hs = [threading.Thread(target=incrementar_seguro)   for _ in range(5)]

for h in hi: h.start()
for h in hi: h.join()

for h in hs: h.start()
for h in hs: h.join()

print(f"Esperado:   500,000")
print(f"Sin lock:   {contador_inseguro:,}   ← distinto en cada ejecución")
print(f"Con lock:   {contador_seguro:,}   ← correcto siempre")
# → Sin lock:   347,821
# → Con lock:   500,000

Dónde se usa

Servidores web

Atender miles de peticiones simultáneas sin bloquear.

GPU / CUDA

Miles de núcleos ejecutando operaciones matriciales en paralelo.

Aplicaciones de escritorio

UI fluida mientras operaciones costosas corren en segundo plano.

Ventajas y desventajas

Ventajas

  • Aprovecha todos los núcleos del procesador
  • Reduce tiempos en tareas de I/O intensivo
  • Sistemas más responsivos y escalables

Desventajas

  • Race conditions y deadlocks muy difíciles de depurar
  • Mayor complejidad de diseño y pruebas
  • La sincronización excesiva anula la ganancia
